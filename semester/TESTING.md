# Тестирование семестровой работы

## 1. Подготовка

Нужен Python 3.11 или новее. Зависимости устанавливать не требуется. В командах ниже `python` означает интерпретатор Python 3.11+. В Linux/macOS он может называться `python3`, в Windows можно использовать `py -3`.

Из корня репозитория скопируйте `semester/starter` в `semester/submission`. Внутри submission должны лежать папка `journal` с файлами `__init__.py`, `models.py`, `storage.py`, `__main__.py` и ваш README. Тесты ищут именно пакет `journal`.

Переносимая команда копирования, выполняется один раз:

```bash
python -c "import shutil; shutil.copytree('semester/starter', 'semester/submission')"
```

Если каталог уже существует, команда специально завершится ошибкой и не перезапишет вашу работу. Продолжайте редактировать созданную копию.

## 2. Запуск

```bash
python semester/run_tests.py --solution semester/submission
python semester/run_tests.py --solution semester/submission --pattern test_models.py
python semester/run_tests.py --solution semester/submission --pattern test_storage.py
```

Запуск без `--solution` проверяет заготовку `starter`, которая намеренно не реализована и должна давать ошибки. Это нормальный результат до выполнения работы, а не образец успешной сдачи.

Проверяется путь, напечатанный в первой строке. Убедитесь, что это ваша реализация. Отсутствие подходящих тестов считается ошибкой запуска. Успех: `OK` и код завершения 0. `FAIL` означает несовпадение результата с ожидаемым, `ERROR` — непредусмотренное исключение. При ошибках код завершения равен 1.

## 3. Как читать ошибку

Допустим, `test_average_empty` сообщает `0 is not None`. Контракт требует `None`, когда оценок нет. Найдите метод `average()`, добавьте отдельную ветку для пустого списка и повторите проверку. Не подменяйте ожидаемое значение в тесте.

Если возник `ModuleNotFoundError: journal`, проверьте структуру каталогов и значение `--solution`. Если возник `NotImplementedError`, соответствующий метод ещё не выполнен. Если тест с `[4, True]` проходит в вашей проверке данных, вспомните, что `bool` является подклассом `int`; для оценок требуется `type(value) is int`.

Тесты используют временные каталоги и не записывают файлы в ваш каталог данных. Они не требуют доступа к интернету. Не запускайте неизвестные чужие решения на машине с важными данными: тестируемая программа — обычный исполняемый Python-код.

## 4. Что проверяет автоматическая проверка

| Область | Проверки |
|---|---|
| Student | Нормализация строк, диапазон оценок, bool и float, независимость списков, среднее, долг, преобразования |
| GradeBook | Уникальность ID, отсутствие студента, поиск, порядок результатов, точный фильтр группы, отчёты |
| JSON | Версия, структура, пустой журнал, дубликаты, повреждение, кодировка, сохранение и повторная загрузка |
| CSV | Заголовок, порядок, точность вывода, отсутствие оценок, экранирование разделителя и кавычек |
| Пример | Совпадение отчёта из demo.json с expected_report.csv |

Количество тестовых методов не равно количеству случаев: один метод может проверять несколько входов через `subTest`. Процент пройденных тестов не является итоговой оценкой. Баллы начисляются по [рубрике](RUBRIC.md).

## 5. Собственные тесты студента

В каталоге решения создайте `tests/test_own.py`. Напишите не менее 8 тестовых методов на `unittest`: обычное вычисление, пустое значение, границу диапазона, неверный тип, дубль ID, сохранение/загрузку, CSV и один обнаруженный вами дефект. Минимум 3 случая должны отличаться от публичных тестов по содержанию проверки, а не только по именам студентов. Кратко объясните различие в отчёте.

```bash
cd semester/submission
python -m unittest discover -s tests -v
```

Не используйте реальные пользовательские файлы. Для тестов файловых операций применяйте `tempfile.TemporaryDirectory()`. Не используйте `sleep` и случайные входы без фиксированного seed. Для среднего сравнивайте через `assertAlmostEqual`.

## 6. Ручная приёмка интерфейса

Из каталога решения выполните `python -m journal`. Формулировки сообщений свободные, поэтому меню проверяется вручную:

1. В пустом журнале открыть список: понятное сообщение, программа продолжает работу.
2. Добавить двух студентов и несколько оценок. В отчёте верный порядок и среднее.
3. Ввести вместо оценки `пять`, затем `6`: сообщение об ошибке, журнал не меняется.
4. Добавить существующий ID: прежняя запись сохраняется.
5. Найти студента частью имени в другом регистре.
6. Запросить неизвестный ID и неизвестную команду: приложение продолжает работу.
7. Отменить удаление, затем подтвердить: оба действия работают ожидаемо.
8. Сохранить JSON, выйти, запустить снова и загрузить файл: данные совпадают.
9. Попытаться загрузить broken.json: текущий журнал остаётся прежним.
10. Загрузить файл при несохранённых изменениях: сначала запросить подтверждение замены.
11. Экспортировать CSV и открыть его текстовым редактором: заголовок и данные соответствуют спецификации.
12. Выйти при несохранённых изменениях: возможность отменить выход. После сохранения предупреждение не требуется.

Тесты модели не доказывают удобство меню и самостоятельность выполнения. Эти пункты и объяснение кода проверяются на защите.
