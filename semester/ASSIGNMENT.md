# Семестровая работа: «Журнал успеваемости»

## 1. Задача

Создайте консольное приложение на Python, с помощью которого преподаватель хранит список студентов, добавляет оценки, получает отчёты и сохраняет данные между запусками. Приложение рассчитано на одного пользователя и один локальный журнал. База данных, веб-сервер и графический интерфейс не требуются.

**Учебная цель:** соединить функции, словари, обработку текста, JSON/CSV, исключения, тесты и простые классы в законченной программе. Основной уровень соответствует материалу семи лекций. Дополнительные возможности выполняются только после завершения обязательного уровня.

**Среда:** Python 3.11+. Только стандартная библиотека. Рекомендуемая самостоятельная работа над проектом — 12–18 часов в течение семестра дополнительно к практикам 13–14. Это ориентир планирования, а не обязательная норма времени для оценки.

## 2. Обязательные возможности

1. Добавление студента с уникальным строковым ID, ФИО и группой.
2. Добавление целой оценки от 2 до 5 выбранному студенту.
3. Вывод списка студентов и отчёта: ID, имя, группа, число оценок, среднее, наличие двоек.
4. Фильтрация отчёта по точному названию группы.
5. Поиск студентов по части имени без учёта регистра.
6. Удаление студента по ID после подтверждения в интерфейсе.
7. Сохранение всего журнала в JSON и загрузка журнала из JSON.
8. Экспорт всего отчёта или выбранной группы в CSV.
9. Понятные сообщения при неверном вводе, повторе ID, отсутствии студента и ошибке файла. После ожидаемой ошибки приложение продолжает работу.
10. Предупреждение перед обычным выходом или загрузкой другого файла, если есть несохранённые изменения. Пользователь может отменить действие.

Вычисление среднего: сумма всех оценок конкретного студента, делённая на их количество. Это не среднее по группе и не среднее из средних. При отсутствии оценок результат `None`, в консоли — «нет оценок», в CSV — пустая ячейка. Долг для этого учебного проекта означает наличие хотя бы одной оценки 2. Отсутствие оценок само по себе долгом не считается. Это правило задания, а не универсальная политика образовательной организации.

## 3. Структура решения

```text
submission/
├── README.md
├── journal/
│   ├── __init__.py
│   ├── __main__.py
│   ├── models.py
│   └── storage.py
├── tests/
│   └── test_own.py

    └── demo.json
```

Пакет `journal` и публичные имена обязательны: тесты импортируют их. Внутренние вспомогательные функции и дополнительные файлы разрешены. Код модели не содержит `input`, меню и файловых операций. Файловый модуль не показывает интерактивное меню. Импорт любого модуля не запускает программу и не создаёт рабочие файлы.

Точные параметры, возвраты, исключения, порядок сортировки и схема файлов описаны в [SPECIFICATION.md](SPECIFICATION.md). При разнице с упрощёнными примерами практик используйте именно итоговую спецификацию.

## 4. Предлагаемое меню

```text
1 — добавить студента
2 — поставить оценку
3 — список и отчёт
4 — поиск по имени
5 — удалить студента
6 — сохранить JSON
7 — загрузить JSON
8 — экспортировать CSV
0 — выход
```

Пункты и формулировки можно изменить, если сохранены все обязательные операции. Пользователь не должен редактировать Python-код, чтобы выбрать файл или группу. Для отчёта пустой ввод группы означает «все группы». ID при вводе в меню очищается через strip. Строковая оценка преобразуется в int в интерфейсе и затем передаётся модели. Неверная команда сообщает об ошибке и возвращает к выбору.

Сохранение выполняется по явной команде. После успешного сохранения или загрузки состояние считается сохранённым. Добавление студента, добавление оценки и удаление делают его несохранённым. Неудачная операция не сбрасывает этот признак. При ошибке загрузки текущие данные остаются прежними. При отказе от удаления данные остаются прежними. При неудачной записи не выводите «Сохранено».

## 5. Этапы работы

| Когда | Результат | Как проверить |
|---|---|---|
| После практики 4 | Таблица полей, примеры студентов, функции поиска и отчёта | Ручные входы и ожидаемые результаты |
| После практики 6 | Нормализация имён, поиск по части имени | Разный регистр, пробелы, пустой запрос |
| После практики 8 | Прототип сохранения и экспорта на словарях | Полный цикл JSON и CSV с кавычками |
| После практики 10 | План тестов и обработка ошибок | Неверные оценки, повреждённый файл |
| После практики 12 | Student и GradeBook по итоговому контракту | Публичные тесты модели |
| Практика 13 | Связанные модель, файлы и меню, собственные тесты | Все публичные тесты и ручной сценарий |
| Практика 14 | Чистая копия, README, исправления, защита | Повторяемый запуск и объяснение кода |

Задание выдается после практики 4. До изучения классов допустим прототип на функциях. Затем перенесите проверенную логику в обязательный API. Не пытайтесь сразу реализовать весь проект: сначала Student, затем GradeBook, затем хранение и меню.

## 6. Индивидуализация

Обязательное ядро у всех одинаковое, чтобы тестирование было прозрачным. Для самостоятельной демонстрации подготовьте собственные вымышленные данные: минимум 6 студентов из двух групп, один без оценок, один с двойкой, два с одинаковым именем и разными ID. Реальные персональные данные не нужны.

Выберите одно необязательное расширение, если базовая часть готова: подсчёт студентов по группам, отдельный список студентов без оценок, выбор отличников с явно описанным правилом или поиск студентов с количеством оценок меньше заданного. Расширение не изменяет обязательные сигнатуры и форматы. Дополнительная часть учитывается внутри рубрики, максимум остаётся 100.

## 7. Что сдать

- Исходный пакет `journal` и README с точными командами.
- Собственные демонстрационные данные и пример CSV-отчёта.
- Минимум 8 тестовых методов unittest, включая 3 содержательно новых случая относительно публичных тестов.
- Короткий отчёт до 3 страниц Markdown: модель данных, устройство программы, таблица проверок, одна найденная ошибка и её исправление, известные ограничения.
- Итог запуска публичных и собственных тестов: команды, число тестов, результат.
- Ссылку на репозиторий решения либо архив без `.venv`, `__pycache__` и временных файлов.

Использование справочников и инструментов помощи отражайте в README: что использовано и что вы проверили самостоятельно. На защите требуется объяснить любой участок сданного кода и выполнить небольшое изменение.

## 8. Приёмка

1. Преподаватель запускает публичные тесты на сданном пакете.
2. Проверяет собственные тесты и ручные сценарии меню из [TESTING.md](TESTING.md).
3. Проводит защиту и выставляет баллы по [RUBRIC.md](RUBRIC.md).

Публичные тесты можно читать, запускать сколько угодно и использовать как уточнение примеров. Изменение или удаление тестов в своей копии не изменяет критерии приёмки. Дополнительные проверки преподавателя могут выбирать другие данные только в пределах опубликованного контракта.
