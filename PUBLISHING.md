# Публикация в Git

Этот каталог подготовлен как содержимое самостоятельного учебного репозитория. Удалённый репозиторий не создан и файлы никуда не отправлены. Данные примеров вымышленные. Решений практик и эталона проекта здесь нет.

## Перед публикацией

1. Прочитайте README и COURSE_GUIDE, назначьте фактические даты и при необходимости уточните принятую схему оценивания.
2. Выполните `python tools/check_materials.py` из корня.
3. Убедитесь, что преподавательский комплект находится отдельно.
4. Определите лицензию публикации и заполните RIGHTS.md. Конкретный правообладатель и лицензия не выдуманы в комплекте.

## Создание репозитория

Из корня этого каталога, если он ещё не является отдельным Git-репозиторием:

```bash
git init -b main
git add .
git commit -m "Добавлен прикладной курс Python для второго курса"
```

Затем создайте пустой удалённый репозиторий в выбранном Git-сервисе. Добавьте его реальный адрес:

```bash
git remote add origin <адрес-вашего-репозитория>
git push -u origin main
```

Угловые скобки в последнем примере обозначают место для реального адреса и не вводятся буквально. В существующий репозиторий скопируйте содержимое каталога через отдельную ветку и проверьте изменения перед слиянием. Не выполняйте повторный git init поверх чужого проекта без необходимости.

## Автоматическая проверка

`.github/workflows/materials.yml` проверяет материалы при push и pull request. Она не требует готового студенческого решения и не пытается зачесть заготовку.

`.github/workflows/submission.yml` запускается вручную с путём к **реализации, уже включённой в текущий репозиторий**. По умолчанию указан `submissions/example`, который намеренно не существует. Перед запуском укажите реальный относительный путь с пакетом journal. Папка semester/submission по умолчанию игнорируется для локальной работы; для проверки решения на GitHub студент размещает реализацию в своём репозитории, например в submissions/my_work, и запускает workflow с этим путём. Ввод передаётся как переменная окружения, а не встраивается в shell-код.

Workflow студенческих решений не использует секреты и имеет только чтение репозитория. Не добавляйте туда ключи доступа и не меняйте триггер на pull_request_target для запуска присланного кода.

## Обновление презентаций

PPTX можно редактировать в PowerPoint или совместимом редакторе. Markdown и JSON в slides/source являются текстовыми исходниками содержания. Для пересборки автономных HTML после изменения JSON выполните `python tools/build_html_slides.py`. Автоматическая сборка PPTX в студенческой среде не требуется; при изменении содержания обновите PPTX отдельно, чтобы форматы не расходились.

HTML-файлы предназначены для локального показа. GitHub показывает их исходный код; для показа скачайте файл и откройте в браузере. Публикация через GitHub Pages необязательна.
