# Практическое занятие 10. Проектирование тестов и исправление дефектов

**Продолжительность:** 90 минут. **Основной уровень:** обязательный для всех. Дополнительное задание выполняется после базовой части.

## Цель

Написать собственные тесты, сначала выявить ошибки, затем исправить реализацию.

## Подготовка и исходные материалы

Прочитайте [лекцию 5](../../lectures/05/README.md). Нужны Python 3.11+, текстовый редактор и терминал. Внешние библиотеки не используются.

В каталоге занятия лежат [starter.py](starter.py), [tests.py](tests.py) и [check.py](check.py). Стартовый файл содержит имена функций и методов, которые ожидают тесты. Заготовка намеренно не проходит проверки до реализации.

Из корня курса один раз подготовьте каталог своей работы и скопируйте заготовку:

```bash
python -c "from pathlib import Path; import shutil; p=Path('student_work/p10'); p.mkdir(parents=True, exist_ok=True); t=p/'solution.py'; assert not t.exists(), 'Решение уже существует'; shutil.copyfile('practices/10/starter.py', t)"
```

Если файл уже существует, продолжайте работу в нём. Не копируйте заготовку поверх своего решения. Команда содержит защитную учебную проверку и запускается без флага `-O`.

## Пошаговая работа

### Задание 1. `average(grades)`

**Контракт.** Корректные оценки, среднее без округления, пустой список → None, вход не меняется. В buggy.py делитель намеренно неверен.

**Пример результата.** average([4, 4]) == 4; average([]) is None.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Выберите вход, где ожидаемое значение очевидно.

### Задание 2. `validate_grade(value)`

**Контракт.** При точном int 2–5 возвращает само значение. Всё остальное даёт ValueError. В buggy.py проверки типов и границ неполны.

**Пример результата.** validate_grade(2) == 2; validate_grade(True) вызывает ValueError.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Разделите границы и неверные типы на самостоятельные случаи.

### Задание 3. `clone_record(record)`

**Контракт.** record содержит ровно name (str) и grades (список целых). Возвращает равный независимый словарь с независимым списком grades. В buggy.py копия поверхностная.

**Пример результата.** Изменение копии grades не меняет исходные оценки.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Тест должен изменить копию после её создания.

## Самопроверка

Из корня курса:

```bash
python practices/10/check.py --solution student_work/p10/solution.py
```

Ожидается `OK`. `FAIL` означает неверный результат проверки, `ERROR` — непредусмотренное исключение. Смотрите имя теста и последнюю строку сообщения. Исправляйте реализацию, а не публичные тесты.

Добавьте минимум три собственных примера, которых нет в таблицах задания. Запишите вход, ожидаемый результат и фактический результат. Для изменяемых коллекций проверьте состояние до и после вызова. На практиках 1–9 достаточно отдельного `self_check.py` с assert; начиная с практики 10 используйте unittest.

## Типичные ошибки

Тесты повторяют неверную формулу; проверяется только равенство копии до изменения; тестовый файл или метод не начинается с test.

## Что сдать

- `solution.py` с реализованными функциями или классами.
- Собственные проверки и таблицу минимум из трёх случаев в `README.md`.
- Короткое объяснение алгоритма: какие шаги выполняются и почему выбран такой результат для пустого входа.
- Результат запуска проверок: команда, число выполненных тестов, итог. Снимок экрана не обязателен.

| Критерий | Баллы |
|---|---:|
| Задание 1 соответствует контракту | 2 |
| Задание 2 соответствует контракту | 2 |
| Задание 3 соответствует контракту | 2 |

Для каждого задания: 2 — выполнено полностью; 1 — основной сценарий работает, но есть локальная ошибка; 0 — нет работающего основного сценария. Дополнительная часть не заменяет обязательную и не увеличивает максимум выше 10.

2. Покажите вход, на котором пришлось изменить первоначальное решение.
3. Какие объекты программа изменяет, а какие создаёт заново?
4. Что произойдёт на пустом входе или при отсутствии совпадений?

## Связь с семестровой работой

Приёмы этой практики можно перенести в журнал успеваемости. Сигнатуры и отдельные правила упражнений могут быть упрощены. В итоговом проекте приоритет имеет [спецификация семестровой работы](../../semester/SPECIFICATION.md), а не имя функции из текущего упражнения.

## Особый порядок для этой практики

1. Откройте [buggy.py](buggy.py). В нём специально оставлены три вида дефектов.
2. Скопируйте его в своё решение вместо starter.py и напишите `test_own.py` с минимум 8 методами unittest **до исправления кода**.
3. Зафиксируйте, какие тесты падают и по какой причине. Обязательно проверьте пустое среднее, обе границы, bool и независимость вложенного списка.
4. Исправьте программу, повторите свои и публичные тесты. Сдайте краткий отчёт «дефект — тест — исправление».

Собственные тесты запускаются из каталога, содержащего solution.py: `python -m unittest discover -s . -p "test_own.py" -v`. Часть проверки самостоятельности преподаватель выполняет по содержанию ваших тестов.
