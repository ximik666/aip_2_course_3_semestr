# Практическое занятие 9. Проверка ввода и исправление ошибок

**Продолжительность:** 90 минут. **Основной уровень:** обязательный для всех. Дополнительное задание выполняется после базовой части.

## Цель

Вызывать ожидаемые исключения и не изменять данные при неудачной операции.

## Подготовка и исходные материалы

Прочитайте [лекцию 5](../../lectures/05/README.md). Нужны Python 3.11+, текстовый редактор и терминал. Внешние библиотеки не используются.

В каталоге занятия лежат [starter.py](starter.py), [tests.py](tests.py) и [check.py](check.py). Стартовый файл содержит имена функций и методов, которые ожидают тесты. Заготовка намеренно не проходит проверки до реализации.

Из корня курса один раз подготовьте каталог своей работы и скопируйте заготовку:

```bash
python -c "from pathlib import Path; import shutil; p=Path('student_work/p09'); p.mkdir(parents=True, exist_ok=True); t=p/'solution.py'; assert not t.exists(), 'Решение уже существует'; shutil.copyfile('practices/09/starter.py', t)"
```

Если файл уже существует, продолжайте работу в нём. Не копируйте заготовку поверх своего решения. Команда содержит защитную учебную проверку и запускается без флага `-O`.

## Пошаговая работа

### Задание 1. `parse_grade(text)`

**Контракт.** Принимает только str. Применяет strip и int, затем проверяет 2–5. Возвращает int. Нестроковый вход, неверная запись или диапазон дают ValueError. Допускаются формы, которые принимает int: например «+4». «4.0» отклоняется.

**Пример результата.** parse_grade(" 4 ") == 4; parse_grade("пять") вызывает ValueError.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Проверьте тип до вызова strip.

### Задание 2. `add_grade_safe(grades, grade)`

**Контракт.** grades — корректный список. grade должен иметь точный тип int и значение 2–5. При успехе добавляет оценку и возвращает None. При ошибке ValueError, список не меняется.

**Пример результата.** Для grades=[4] попытка добавить True даёт ValueError и grades == [4].

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Порядок: проверить, затем append.

### Задание 3. `get_record(book, student_id)`

**Контракт.** book — словарь. Возвращает значение по точному ключу student_id. Если ID отсутствует, вызывает KeyError. Не печатает сообщения и не заменяет ошибку пустым словарём.

**Пример результата.** get_record({"1":{"name":"А"}}, "1") возвращает эту запись.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Квадратные скобки уже имеют нужное поведение.

## Самопроверка

Из корня курса:

```bash
python practices/09/check.py --solution student_work/p09/solution.py
```

Ожидается `OK`. `FAIL` означает неверный результат проверки, `ERROR` — непредусмотренное исключение. Смотрите имя теста и последнюю строку сообщения. Исправляйте реализацию, а не публичные тесты.

Добавьте минимум три собственных примера, которых нет в таблицах задания. Запишите вход, ожидаемый результат и фактический результат. Для изменяемых коллекций проверьте состояние до и после вызова. На практиках 1–9 достаточно отдельного `self_check.py` с assert; начиная с практики 10 используйте unittest.

## Типичные ошибки

isinstance(True, int) принимает bool; append до проверки портит данные; широкий except маскирует ошибки программиста.
