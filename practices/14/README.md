# Практическое занятие 14. Проверка, доработка и защита

**Продолжительность:** 90 минут. Оценка ставится по [рубрике семестровой работы](../../semester/RUBRIC.md). Практика не дублирует баллы проекта.

## Цель

Подтвердить, что программу можно запустить из сданной копии, её поведение соответствует контракту, а автор понимает решение. Завершить документацию и продемонстрировать небольшое изменение с проверкой.

## До занятия

Подготовьте исходники, собственные демонстрационные данные, CSV-отчёт, минимум восемь собственных тестов и заполненный [шаблон отчёта](../../semester/REPORT_TEMPLATE.md). Все публичные тесты должны быть запущены заранее. Если остались ошибки, перечислите их явно; не скрывайте результат запуска.

## План

| Время | Работа |
|---|---|
| 0–15 | Проверка из чистой копии, запуск тестов |
| 15–30 | Взаимная ручная приёмка по чек-листу |
| 30–45 | Небольшое индивидуальное изменение и тест |
| 45–85 | Защиты по расписанию преподавателя, остальные завершают отчёт |
| 85–90 | Фиксация итоговой версии и сдача |

Для группы более 8–10 студентов полные индивидуальные защиты по 7–8 минут не помещаются в одну пару. Преподаватель начинает часть защит на практике 13, выделяет дополнительное согласованное время либо проводит короткую индивидуальную демонстрацию после заранее проверенных тестов и отчёта. Ожидание очереди не заменяет проверку понимания каждого автора.

## Задание 1. Чистая копия

Скопируйте только сдаваемые файлы в новый каталог. Следуйте собственному README. Убедитесь, что Python находит пакет journal, импорт не запускает меню, данные не зависят от старого рабочего каталога. Запустите публичные тесты, указав путь к новой копии через --solution, и собственные тесты из каталога решения.

Ожидаемый результат: тот же набор успешных проверок, что в рабочем каталоге. Если результат отличается, найдите отсутствующий файл или неявную зависимость и исправьте инструкцию либо комплект.

## Задание 2. Взаимная приёмка

Передайте одногруппнику инструкцию и вымышленные данные. Он выполняет сценарии из раздела ручной приёмки [TESTING.md](../../semester/TESTING.md), записывая «ожидание — фактический результат». Автор наблюдает и отвечает после выполнения сценария, чтобы не подменять документацию устными подсказками.

Обязательные случаи: пустой журнал, одинаковые имена с разными ID, неверная оценка, неизвестный ID, отмена удаления, сохранение/восстановление, повреждённый JSON и выход без сохранения. Замечания одногруппника не являются окончательной оценкой, но помогают обнаружить пропуски.

## Задание 3. Индивидуальное изменение

Преподаватель выбирает один вариант:

- Добавить отдельную функцию списка студентов без оценок.
- Добавить отдельную функцию подсчёта студентов по группам.
- Добавить собственный тест сохранения после удаления последнего студента.
- Добавить пункт меню, показывающий количество студентов выбранной группы.

Перед кодом запишите контракт и один ожидаемый пример. Существующий API и формат файлов не изменяйте. После изменения повторите связанные проверки и полный публичный набор. На защите объясните, почему изменение не нарушило прежние функции.

## Задание 4. Защита

Покажите путь данных через приложение, один отрицательный сценарий и один содержательный собственный тест. Ответьте на вопросы преподавателя и предъявите выполненное изменение. Не зачитывайте весь исходный код: объясняйте ответственность модулей и конкретное поведение.

Пример вопроса: «Почему to_dict копирует список, а get_student возвращает хранимый объект?» Ожидается объяснение двух разных контрактов, а не утверждение «копировать нужно всегда».

## Итог сдачи

Ссылка или архив содержит только окончательную версию. В README указаны версия Python, запуск, тесты, формат данных и ограничения. В отчёте есть фактический результат проверок. Получите лист приёмки с баллами и конкретными замечаниями. При доработке исправьте перечисленные требования и повторите те же проверки, а не создавайте несвязанный новый проект.
