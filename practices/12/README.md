# Практическое занятие 12. Класс GradeBook и композиция

**Продолжительность:** 90 минут. **Основной уровень:** обязательный для всех. Дополнительное задание выполняется после базовой части.

## Цель

Создать контейнер объектов Student с поиском по ID и отчётом.

## Подготовка и исходные материалы

Прочитайте [лекцию 6](../../lectures/06/README.md). Нужны Python 3.11+, текстовый редактор и терминал. Внешние библиотеки не используются.

В каталоге занятия лежат [starter.py](starter.py), [tests.py](tests.py) и [check.py](check.py). Стартовый файл содержит имена функций и методов, которые ожидают тесты. Заготовка намеренно не проходит проверки до реализации.

Из корня курса один раз подготовьте каталог своей работы и скопируйте заготовку:

```bash
python -c "from pathlib import Path; import shutil; p=Path('student_work/p12'); p.mkdir(parents=True, exist_ok=True); t=p/'solution.py'; assert not t.exists(), 'Решение уже существует'; shutil.copyfile('practices/12/starter.py', t)"
```

Если файл уже существует, продолжайте работу в нём. Не копируйте заготовку поверх своего решения. Команда содержит защитную учебную проверку и запускается без флага `-O`.

## Пошаговая работа

### Задание 1. `GradeBook(), GradeBook.add(student_id, student)`

**Контракт.** Начальный журнал пуст. add принимает непустую str ID без краевых пробелов и объект Student из заготовки. Неверные аргументы или повтор ID дают ValueError. Хранит переданный объект. Возвращает None. Сам класс Student уже готов и не изменяется.

**Пример результата.** book.add("1", Student("Анна")); book.get("1") возвращает этот же объект.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Словарь ID → Student создаётся в __init__.

### Задание 2. `GradeBook.get(student_id), GradeBook.add_grade(student_id, grade)`

**Контракт.** По точному ID возвращает объект либо KeyError. add_grade делегирует проверку Student.add_grade, возвращает None. Отсутствие ID даёт KeyError.

**Пример результата.** После book.add_grade("1", 5) у студента есть оценка 5.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Журнал ищет студента, студент проверяет оценку.

### Задание 3. `GradeBook.report()`

**Контракт.** Возвращает список словарей с ровно id, name, average, отсортированный по строковому ID. Пустой журнал → []. average не округляется или None. В отличие от семестровой работы этот учебный отчёт сортируется по ID.

**Пример результата.** Для ID 2 и 1 строки отчёта идут как 1, 2.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** sorted(self._students.items()) возвращает пары в порядке ключей.

## Самопроверка

Из корня курса:

```bash
python practices/12/check.py --solution student_work/p12/solution.py
```

Ожидается `OK`. `FAIL` означает неверный результат проверки, `ERROR` — непредусмотренное исключение. Смотрите имя теста и последнюю строку сообщения. Исправляйте реализацию, а не публичные тесты.

Добавьте минимум три собственных примера, которых нет в таблицах задания. Запишите вход, ожидаемый результат и фактический результат. Для изменяемых коллекций проверьте состояние до и после вызова. На практиках 1–9 достаточно отдельного `self_check.py` с assert; начиная с практики 10 используйте unittest.

## Типичные ошибки

Повторная реализация проверки оценок в журнале; молчаливая замена ID; перенос упрощённого порядка сортировки в итоговый проект.
