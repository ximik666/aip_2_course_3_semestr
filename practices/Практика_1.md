# Практическая работа «Обработка заказов интернет-магазина»

**Продолжительность:** 90 минут.  
**Основная тема:** словари, вложенные структуры, поиск по ключу и накопление статистики.

## Ситуация

Небольшой интернет-магазин получает заказы покупателей. Нужно написать программу, которая проверяет возможность выполнения каждого заказа, уменьшает остатки товаров и формирует отчёт о продажах.

Все данные находятся в программе. Ввод через клавиатуру, файлы и интерактивное меню не требуются.

## Исходные данные

Каталог хранится в словаре. Ключ — артикул, значение — словарь характеристик товара. Цены указаны в целых рублях.

```python
catalog = {
    "P01": {"name": "Тетрадь",   "price": 80,  "stock": 12},
    "P02": {"name": "Ручка",     "price": 50,  "stock": 20},
    "P03": {"name": "Папка",     "price": 120, "stock": 5},
    "P04": {"name": "Маркер",    "price": 90,  "stock": 8},
    "P05": {"name": "Блокнот",   "price": 200, "stock": 4},
}

orders = [
    {
        "id": "O01",
        "customer": "Анна",
        "items": [("P01", 3), ("P02", 2), ("P01", 1)],
    },
    {
        "id": "O02",
        "customer": "Борис",
        "items": [("P03", 2), ("P05", 1)],
    },
    {
        "id": "O03",
        "customer": "Анна",
        "items": [("P05", 4), ("P02", 1)],
    },
    {
        "id": "O04",
        "customer": "Вера",
        "items": [("P09", 1), ("P01", 2)],
    },
    {
        "id": "O05",
        "customer": "Борис",
        "items": [("P04", 3), ("P02", 4)],
    },
    {
        "id": "O06",
        "customer": "Глеб",
        "items": [("P01", 0), ("P02", 2)],
    },
    {
        "id": "O07",
        "customer": "Анна",
        "items": [("P03", 3), ("P01", 2)],
    },
]
```

Считайте, что идентификаторы заказов уникальны, обязательные поля присутствуют, артикулы и имена являются строками. Проверять нужно содержимое `items` по правилам ниже.

## Главная задача

Обработайте заказы **в порядке их расположения в списке**. Для каждого заказа получите результат обработки, затем сформируйте общую статистику.

### 1. Объединение повторяющихся товаров

Один артикул может встречаться в заказе несколько раз. Перед проверкой остатков объедините такие позиции в словарь:

```python
[("P01", 3), ("P02", 2), ("P01", 1)]
```

Результат:

```python
{"P01": 4, "P02": 2}
```

Количество в каждой исходной позиции должно иметь точный тип `int` и быть больше нуля. Значения `True`, `"2"`, `2.5`, `0` и отрицательные числа недопустимы.

**Проверяйте количества до объединения:** позиции с количествами `3` и `-1` не должны превращаться в допустимое количество `2`.

### 2. Проверка заказа

Отклоните заказ, если:

- список позиций пуст;
- хотя бы одно количество недопустимо;
- артикул отсутствует в каталоге;
- объединённое количество товара превышает текущий остаток.

Достаточно сообщить одну причину. Чтобы результат был предсказуемым, сначала проверяйте пустоту и количества, затем неизвестные артикулы, затем остатки. Внутри каждого этапа используйте порядок первого появления товаров.

### 3. Выполнение заказа

Если все проверки пройдены:

1. Рассчитайте стоимость каждой объединённой позиции.
2. Рассчитайте общую стоимость.
3. Уменьшите остатки всех товаров заказа.
4. Добавьте сведения о продаже в статистику.

**Заказ выполняется целиком либо отклоняется целиком.** При отказе остатки и статистика не меняются.

Например, для заказа `O03` не хватает блокнотов. Поэтому ручка из этого заказа тоже не продаётся.

### 4. Результаты обработки

Создайте словарь результатов, ключом которого является идентификатор заказа.

Успешный результат:

```python
{
    "status": "accepted",
    "total": 420,
    "items": {"P01": 4, "P02": 2},
}
```

Отказ:

```python
{
    "status": "rejected",
    "reason": "Недостаточно товара P05: нужно 4, доступно 3",
}
```

Формулировка причины может отличаться, но должна объяснять ошибку.

### 5. Итоговый отчёт

Сформируйте и выведите:

- количество принятых и отклонённых заказов;
- общую выручку;
- словарь `покупатель → сумма успешных покупок`;
- словарь `артикул → проданное количество`, включая товары с нулевыми продажами;
- остатки всех товаров;
- самый продаваемый товар по количеству.

При равенстве продаж выберите лексикографически минимальный артикул. Если продаж нет, верните `None`.

## Организация решения

Выделите минимум три функции:

```python
prepare_order(items, catalog)
process_orders(catalog, orders)
print_report(results, statistics, catalog)
```

`prepare_order` проверяет заказ и возвращает подготовленные позиции либо причину отказа. **Эта функция не изменяет каталог.**

`process_orders` последовательно обрабатывает заказы, изменяет остатки только после успешной проверки и возвращает результаты со статистикой.

`print_report` отвечает только за вывод.

Формат возвращаемого значения первой функции выберите самостоятельно и опишите в комментарии.

## Обязательные проверки

Кроме основного примера проверьте:

1. Пустой список заказов: выручка равна нулю, лидер продаж — `None`.
2. Пустой заказ: отказ.
3. Заказ ровно на весь остаток товара: успех, остаток становится нулём.
4. Повторяющиеся позиции, сумма которых превышает остаток: отказ.
5. Заказ с допустимой первой позицией и ошибочной второй: остатки **всех** товаров сохраняются.
6. Два последовательных заказа на один товар: второй проверяется по остатку после первого.

Каждую независимую проверку запускайте с новым каталогом. Для вложенных словарей обычный `catalog.copy()` не создаёт независимые копии характеристик товаров. Можно использовать `copy.deepcopy()`.
