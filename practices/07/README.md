## Пошаговая работа

### Задание 1. `save_records(records, path)`

**Контракт.** records — JSON-совместимый список словарей. Записывает его как один JSON-массив в UTF-8, кириллица читаемая. Существующий файл заменяется. Возвращает None. path — str или Path, родительский каталог уже существует.

**Пример результата.** После save_records([{"name":"Анна"}], path) файл содержит JSON-массив с этой записью.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Используйте ensure_ascii=False и явную кодировку.

### Задание 2. `load_records(path)`

**Контракт.** Читает UTF-8 JSON и возвращает список. Если корень не список, вызывает ValueError. Отсутствие файла даёт FileNotFoundError. Повреждённый JSON допускается как JSONDecodeError, являющийся подклассом ValueError. Поля отдельных записей пока не проверяются.

**Пример результата.** JSON [] загружается как [], JSON {} вызывает ValueError.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Разделите разбор формата и проверку типа корневого значения.

### Задание 3. `copy_records(records)`

**Контракт.** Создаёт независимую копию JSON-совместимых данных полным циклом dumps/loads. Предполагаются только строковые ключи, списки и простые JSON-типы. Вложенные списки должны быть независимыми.

**Пример результата.** Изменение result[0]["grades"] не меняет исходный список.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Это учебное применение сериализации, а не универсальная копия произвольных объектов Python.

## Самопроверка

Из корня курса:

```bash
python practices/07/check.py --solution student_work/p07/solution.py
```

Ожидается `OK`. `FAIL` означает неверный результат проверки, `ERROR` — непредусмотренное исключение. Смотрите имя теста и последнюю строку сообщения. Исправляйте реализацию, а не публичные тесты.

Добавьте минимум три собственных примера, которых нет в таблицах задания. Запишите вход, ожидаемый результат и фактический результат. Для изменяемых коллекций проверьте состояние до и после вызова. На практиках 1–9 достаточно отдельного `self_check.py` с assert; начиная с практики 10 используйте unittest.

## Типичные ошибки

Запись через str вместо JSON; добавление второго документа режимом a; чтение без UTF-8; сравнение только существования файла.
