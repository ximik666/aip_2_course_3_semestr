# Практическое занятие 2. Небольшой журнал на функциях

**Продолжительность:** 90 минут. **Основной уровень:** обязательный для всех. Дополнительное задание выполняется после базовой части.

## Цель

Соединить функции вычисления с добавлением данных и формированием отчёта.

## Подготовка и исходные материалы

Прочитайте [лекцию 1](../../lectures/01/README.md). Нужны Python 3.11+, текстовый редактор и терминал. Внешние библиотеки не используются.

В каталоге занятия лежат [starter.py](starter.py), [tests.py](tests.py) и [check.py](check.py). Стартовый файл содержит имена функций и методов, которые ожидают тесты. Заготовка намеренно не проходит проверки до реализации.

Из корня курса один раз подготовьте каталог своей работы и скопируйте заготовку:

```bash
python -c "from pathlib import Path; import shutil; p=Path('student_work/p02'); p.mkdir(parents=True, exist_ok=True); t=p/'solution.py'; assert not t.exists(), 'Решение уже существует'; shutil.copyfile('practices/02/starter.py', t)"
```

Если файл уже существует, продолжайте работу в нём. Не копируйте заготовку поверх своего решения. Команда содержит защитную учебную проверку и запускается без флага `-O`.

## Пошаговая работа

### Задание 1. `append_grade(grades, grade)`

**Контракт.** На корректных данных возвращает новый список с добавленной оценкой. Исходный список остаётся прежним. В этой практике grade уже находится в диапазоне 2–5.

**Пример результата.** append_grade([4], 5) == [4, 5], исходный список == [4].

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Скопируйте список до добавления.

### Задание 2. `student_summary(name, grades)`

**Контракт.** Возвращает новый словарь с ровно полями name, count, average, debt. average — число без округления либо None, debt — bool, означающий наличие хотя бы одной двойки.

**Пример результата.** student_summary("А", [2, 5]) == {"name":"А", "count":2, "average":3.5, "debt":True}.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** Соберите именованные поля. Не обозначайте отсутствие оценок нулём.

### Задание 3. `make_report(records)`

**Контракт.** records — список словарей с полями name и grades. Возвращает список student_summary для каждой записи в исходном порядке. Пустой вход даёт []. Входные данные не изменяет.

**Пример результата.** make_report([{"name":"А", "grades":[]}])[0]["average"] is None.

**Порядок выполнения:**

1. Выпишите допустимые входы и тип результата.
2. Рассчитайте результат примера вручную и запишите его рядом с решением.
3. Реализуйте функцию или методы в `solution.py`, сохранив указанные имена.
4. Проверьте пример и один отличающийся случай. Объясните, меняет ли операция входные данные.

**Подсказка при затруднении.** В цикле вызывайте student_summary, а не повторяйте её вычисления.

## Самопроверка

Из корня курса:

```bash
python practices/02/check.py --solution student_work/p02/solution.py
```

Ожидается `OK`. `FAIL` означает неверный результат проверки, `ERROR` — непредусмотренное исключение. Смотрите имя теста и последнюю строку сообщения. Исправляйте реализацию, а не публичные тесты.

Добавьте минимум три собственных примера, которых нет в таблицах задания. Запишите вход, ожидаемый результат и фактический результат. Для изменяемых коллекций проверьте состояние до и после вызова. На практиках 1–9 достаточно отдельного `self_check.py` с assert; начиная с практики 10 используйте unittest.

## Типичные ошибки

Общий список вместо копии; True для студента без оценок; сортировка там, где требуется исходный порядок.

## Что сдать

- `solution.py` с реализованными функциями или классами.
- Собственные проверки и таблицу минимум из трёх случаев в `README.md`.
- Короткое объяснение алгоритма: какие шаги выполняются и почему выбран такой результат для пустого входа.
- Результат запуска проверок: команда, число выполненных тестов, итог. Снимок экрана не обязателен.

4. Что произойдёт на пустом входе или при отсутствии совпадений?
