Ещё одна задача на **90 минут** — распределение студентов по учебным группам. Здесь словари используются для поиска записей, устранения повторов, группировки и формирования отчётов.

# Практическая работа «Запись студентов на факультативы»

**Продолжительность:** 90 минут.  
**Тема:** словари, вложенные структуры и обработка связанных данных.

## Ситуация

Университет открывает факультативы. Студенты подают заявки, но количество мест ограничено. Некоторые заявки повторяются, содержат неизвестные идентификаторы или создают пересечение занятий по времени.

Разработайте программу, которая обрабатывает заявки и формирует списки участников, очереди ожидания и индивидуальные расписания.

Ввод через клавиатуру, файлы, классы и внешние библиотеки не требуются.

## Исходные данные

Идентификатор студента является ключом словаря. Имена могут совпадать, поэтому использовать имя вместо идентификатора нельзя.

```python
students = {
    "S01": {"name": "Анна", "group": "ИВТ-201"},
    "S02": {"name": "Борис", "group": "ИВТ-201"},
    "S03": {"name": "Вера", "group": "ИВТ-202"},
    "S04": {"name": "Глеб", "group": "ИВТ-202"},
    "S05": {"name": "Дина", "group": "ИВТ-201"},
    "S06": {"name": "Егор", "group": "ИВТ-202"},
}

courses = {
    "PY": {
        "title": "Практический Python",
        "slot": "Пн 16:00",
        "capacity": 2,
    },
    "WEB": {
        "title": "Веб-разработка",
        "slot": "Пн 16:00",
        "capacity": 2,
    },
    "DATA": {
        "title": "Анализ данных",
        "slot": "Ср 16:00",
        "capacity": 2,
    },
    "ROBOT": {
        "title": "Робототехника",
        "slot": "Пт 16:00",
        "capacity": 2,
    },
}

applications = [
    ("S01", "PY"),
    ("S02", "PY"),
    ("S03", "PY"),
    ("S01", "WEB"),
    ("S03", "WEB"),
    ("S04", "DATA"),
    ("S05", "DATA"),
    ("S06", "DATA"),
    ("S02", "ROBOT"),
    ("S02", "ROBOT"),
    ("S07", "PY"),
    ("S05", "DESIGN"),
    ("S01", "DATA"),
    ("S06", "ROBOT"),
]
```

Каждая заявка — пара `(идентификатор студента, код факультатива)`.

Считайте, что структура исходных данных корректна, вместимость — положительное целое число. Совпадение строк `slot` означает полное совпадение времени занятий.

## Правила обработки

Обрабатывайте заявки строго по порядку. Для каждой заявки выполните следующие проверки:

1. **Существование студента и факультатива.**  
   Если идентификатор неизвестен, отклоните заявку. Если неизвестны оба, сначала сообщите об ошибке студента.

2. **Повторная заявка.**  
   Если студент уже зачислен на этот факультатив или находится в его очереди ожидания, отклоните повтор. Ранее отклонённая заявка повтором не считается.

3. **Пересечение времени.**  
   Если студент уже зачислен на другой факультатив с таким же `slot`, отклоните заявку.

4. **Свободные места.**  
   Если место есть — зачислите студента. Если мест нет — добавьте его в очередь ожидания.

**Очередь ожидания не занимает время в расписании.** Студент может ожидать место на одном факультативе и быть зачисленным на другой в тот же временной слот.

Автоматическое продвижение из очереди в основной части задания не требуется.

## Что нужно реализовать

### 1. Списки участников

Создайте словарь:

```python
enrolled = {
    "PY": [],
    "WEB": [],
    "DATA": [],
    "ROBOT": [],
}
```

Значение — список идентификаторов зачисленных студентов в порядке зачисления.

Списки разных факультативов должны быть независимыми.

### 2. Очереди ожидания

Создайте аналогичный словарь `waiting`.

Сохраняйте порядок поступления заявок. Один студент не должен появляться в очереди одного факультатива дважды.

### 3. Индивидуальные расписания

Создайте словарь, в котором каждому студенту соответствует словарь `временной слот → код факультатива`.

Пример:

```python
schedule = {
    "S01": {"Пн 16:00": "PY"},
    "S02": {
        "Пн 16:00": "PY",
        "Пт 16:00": "ROBOT",
    },
}
```

В итоговой структуре должны присутствовать **все студенты**. Если студент никуда не зачислен, его расписание равно `{}`.

Используйте эту структуру для проверки пересечений.

### 4. Журнал обработки

Сохраните результат каждой заявки в словаре. Ключ — порядковый номер заявки, начиная с 1.

Пример успешного результата:

```python
{
    "student": "S01",
    "course": "PY",
    "status": "enrolled",
    "reason": "Есть свободное место",
}
```

Допустимые статусы:

- `enrolled` — студент зачислен;
- `waiting` — добавлен в очередь;
- `rejected` — заявка отклонена.

Для отказа укажите конкретную причину: неизвестный студент, неизвестный факультатив, повторная заявка или пересечение времени.

### 5. Итоговый отчёт

Программа должна вывести:

- количество заявок каждого статуса;
- участников каждого факультатива с именами и учебными группами;
- очереди ожидания;
- количество свободных мест на каждом факультативе;
- индивидуальные расписания всех студентов;
- студентов, которые никуда не зачислены;
- факультатив с самой длинной очередью.

Если максимальная очередь одинакова у нескольких факультативов, выведите все такие факультативы по возрастанию кода. Если все очереди пусты, выведите «Очередей нет».

## Организация программы

Выделите минимум три функции:

```python
process_applications(students, courses, applications)
build_statistics(enrolled, waiting, schedule, results, courses)

```

Первая функция возвращает:

```python
enrolled, waiting, schedule, results
```

Вторая рассчитывает показатели отчёта. Третья выводит результат в понятном виде.

Исходные словари `students`, `courses` и список `applications` изменять нельзя. Все рабочие структуры создаются отдельно.

## Контрольные результаты

После обработки исходных заявок:

| Факультатив | Зачислены | Очередь | Свободные места |
|---|---|---|---:|
| PY | S01, S02 | S03 | 0 |
| WEB | S03 | — | 1 |
| DATA | S04, S05 | S06, S01 | 0 |
| ROBOT | S02, S06 | — | 0 |

Статистика заявок:

```python
{
    "enrolled": 7,
    "waiting": 3,
    "rejected": 4,
}
```

Причины отказов:

- заявка №4 — у S01 уже есть занятие в понедельник в 16:00;
- заявка №10 — повторная запись S02 на ROBOT;
- заявка №11 — неизвестный студент S07;
- заявка №12 — неизвестный факультатив DESIGN.

Все шесть студентов зачислены хотя бы на один факультатив. Самая длинная очередь — у `DATA`, два человека.

**Обратите внимание:** S03 остаётся в очереди на PY и одновременно зачислен на WEB. По правилам задачи это допустимо.

## Обязательные проверки

Подготовьте отдельные небольшие наборы данных для следующих ситуаций:

1. Заявок нет: все списки пусты, места свободны, расписания равны `{}`.
2. Заявок ровно столько, сколько мест: все студенты зачислены.
3. Мест не хватает: лишняя заявка попадает в очередь.
4. Повторная заявка уже зачисленного студента: отказ.
5. Повторная заявка студента из очереди: отказ без дублирования.
6. Два факультатива в одно время: зачисление на второй отклоняется.
7. Самые длинные очереди одинаковы: отчёт показывает несколько факультативов.

Дополнительно убедитесь, что изменение списка участников одного факультатива не меняет списки остальных.
