## 1. Состояние программы и файл

Словарь существует в памяти запущенной программы. После завершения процесса он не восстанавливается автоматически. Сохранение переводит данные в последовательность символов или байтов, а загрузка выполняет обратное преобразование. Это называется сериализацией и десериализацией.

Перед выбором формата определяем назначение файла. Если нужно сохранить студентов с разным количеством оценок, удобна вложенная структура JSON. Если нужно передать итоговый отчёт в табличный редактор, удобен CSV: одна строка на студента, одинаковые столбцы. Один и тот же формат не обязан решать обе задачи.

Путь к файлу также является входным значением. Относительный путь отсчитывается от текущего рабочего каталога процесса, а не автоматически от расположения Python-файла. Поэтому в инструкции запуска обязательно указываем каталог. В переносимых программах используем pathlib, чтобы не собирать пути вручную через слеши.

### Демонстрация 1

Полный запускаемый пример: [examples/section_01.py](examples/section_01.py).

```python

base = Path("data")
path = base / "journal.json"

print(path.suffix)
print(path.parent.name)
```

```text

data
```

## 2. JSON и типы данных

JSON описывает объекты, массивы, строки, числа, логические значения и null. В Python им соответствуют словари, списки, строки, числа, bool и None. Для учебного формата используем только строковые ключи. Не все объекты Python можно напрямую сохранить: экземпляр собственного класса потребуется сначала преобразовать в словарь.

json.dumps превращает структуру Python в строку, а json.loads разбирает строку. Параметр ensure_ascii=False оставляет русские буквы читаемыми. Без него данные также можно восстановить, но текст файла будет содержать escape-последовательности. indent делает структуру удобной для чтения человеком и просмотра изменений в Git.

Синтаксически корректный JSON ещё не гарантирует правильность данных. Объект {"grades": [9]} успешно разбирается, но нарушает шкалу оценок. Поэтому после разбора следует отдельная проверка полей. Сначала изучаем преобразование формата, а на следующей лекции оформим обработку ошибок.

### Демонстрация 2

Полный запускаемый пример: [examples/section_02.py](examples/section_02.py).

```python
import json

student = {"name": "Анна", "grades": [4, 5], "active": True}
text = json.dumps(student, ensure_ascii=False)
print(text)
restored = json.loads(text)
print(restored == student)
```

**Ожидаемый вывод:**

```text
{"name": "Анна", "grades": [4, 5], "active": true}
True
```

**Вопрос для обсуждения:** Можно ли считать оценки верными только потому, что loads завершился успешно?

## 3. Чтение и запись UTF-8

При работе с текстовыми файлами явно задаём encoding="utf-8". Это делает обработку русских букв одинаковой на разных системах. Конструкция with закрывает файл при выходе из блока, включая случай исключения. Для коротких текстов pathlib предлагает read_text и write_text с тем же явным указанием кодировки.

Режим w заменяет содержимое существующего файла. Поэтому учебная демонстрация использует временный каталог, а рабочее приложение должно явно сообщать, какой файл сохраняется. Режим a добавляет текст в конец и не подходит для сохранения единственного JSON-документа: несколько документов подряд не образуют один корректный документ.

Проверку сохранения выполняем полным циклом: создать данные, записать, прочитать, сравнить. Недостаточно убедиться, что файл появился. Он может содержать неполные данные или неверную кодировку. Сравниваем структуры, а не форматирование пробелов в JSON.

### Демонстрация 3

Полный запускаемый пример: [examples/section_03.py](examples/section_03.py).

```python
import json
import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as folder:
    path = Path(folder) / "data.json"
    path.write_text(json.dumps(["Анна"], ensure_ascii=False), encoding="utf-8")
    loaded = json.loads(path.read_text(encoding="utf-8"))
    print(loaded)
```

**Ожидаемый вывод:**

```text
['Анна']
```

**Вопрос для обсуждения:** Почему режим a не подходит для обычного файла журнала JSON?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 4. CSV и разделители

CSV хранит строки с одинаковым набором столбцов. Несмотря на название, разделителем может быть точка с запятой. Его необходимо явно согласовать при записи и чтении. Модуль csv умеет экранировать разделитель, кавычки и переводы строк внутри значения. Самостоятельное разбиение через split(";") этих правил не учитывает.

DictReader использует заголовок как имена полей и возвращает каждую строку как словарь. Значения при чтении являются строками. Если столбец grade должен содержать число, выполняем отдельное преобразование int и проверку диапазона. Пустая ячейка тоже остаётся строкой, поэтому её смысл нужно определить заранее.

Файлы CSV открываем с newline="", чтобы модуль управлял переводами строк. В демонстрации используется StringIO — текстовый поток в памяти. Он позволяет увидеть поведение CSV без создания постоянного файла и пригодится для коротких тестов.

### Демонстрация 4

Полный запускаемый пример: [examples/section_04.py](examples/section_04.py).

```python
import csv
import io

source = 'name;grade\n"Анна; староста";5\n'
rows = list(csv.DictReader(io.StringIO(source), delimiter=";"))
print(rows[0]["name"])
print(int(rows[0]["grade"]) + 1)
```

**Ожидаемый вывод:**

```text
Анна; староста
6
```

**Вопрос для обсуждения:** Что сломает split(";") в этом примере?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 5. Экспорт отчёта

При экспорте сначала формируем строки отчёта, затем передаём их DictWriter. Список fieldnames определяет состав и порядок столбцов. writeheader записывает заголовок даже при отсутствии строк. Благодаря этому пустой отчёт остаётся корректной таблицей известной структуры.

Числовое среднее удобно вычислять без округления, а в отчёте преобразовывать в строку с двумя знаками. Для отсутствия оценок используем пустую ячейку. Логическое поле долга в семестровом формате записывается как yes или no. Это заранее согласованные значения, а не результат случайного преобразования bool в строку.

Не изменяйте исходный словарь отчёта только ради оформления CSV, если другие части программы ещё используют числовые значения. Создайте отдельную строку или копию. Так экспорт не превратит данные приложения из чисел в строки.

### Демонстрация 5

Полный запускаемый пример: [examples/section_05.py](examples/section_05.py).

```python
import csv
import io

stream = io.StringIO(newline="")
writer = csv.DictWriter(stream, fieldnames=["name", "average"], delimiter=";")
writer.writeheader()
writer.writerow({"name": "Анна", "average": f"{14 / 3:.2f}"})
print(stream.getvalue(), end="")
```

**Ожидаемый вывод:**

```text
name;average
Анна;4.67
```

**Вопрос для обсуждения:** Зачем сохранять заголовок, если в отчёте нет студентов?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 6. Версия и схема документа

Формат файла со временем может измениться. Небольшое поле version позволяет отличить знакомую структуру от неизвестной. В нашем журнале корневой объект содержит version=1 и список students. При неподдерживаемой версии загрузчик должен сообщить об ошибке, а не пытаться молча угадать смысл полей.

Проверка схемы отвечает на конкретные вопросы: корень является словарём? Есть обязательные поля? students является списком? Каждый элемент содержит ID, имя, группу и оценки? ID уникальны? Для учебного проекта лишние поля также считаются нарушением, чтобы контракт оставался однозначным.

В примере показываем простую диагностическую проверку корня. Полная проверка будет частью семестровой работы. Не загружайте часть правильных записей, молча пропуская неправильные: пользователь решит, что восстановлен весь журнал. Сначала проверяем новый объект полностью, затем заменяем им текущее состояние.

### Демонстрация 6

Полный запускаемый пример: [examples/section_06.py](examples/section_06.py).

```python
def valid_root(data):
    return (isinstance(data, dict)
            and set(data) == {"version", "students"}
            and type(data["version"]) is int
            and data["version"] == 1
            and isinstance(data["students"], list))

print(valid_root({"version": 1, "students": []}))
print(valid_root({"version": True, "students": []}))
```

**Ожидаемый вывод:**

```text
True
False
```

**Вопрос для обсуждения:** Почему проверка версии включает type(...) is int?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 7. Проверка полного цикла

Полный цикл сохранения и загрузки проверяет взаимодействие преобразований. Создайте вход, сохраните, загрузите и сравните структуру. Затем измените восстановленные данные и убедитесь, что это не влияет на исходный объект в памяти. Сериализация создаёт новые контейнеры при разборе, что удобно для независимого состояния.

Кроме удачного сценария нужны пустой документ принятой схемы, отсутствующий файл, повреждённый синтаксис и неверная оценка внутри правильного JSON. Эти случаи относятся к разным уровням проверки. Пока обсуждаем ожидаемое поведение словами; следующая лекция даст механизм исключений и автоматических тестов.

Рабочие файлы пользователей и учебные примеры следует разделять. Пример в репозитории должен оставаться неизменным, чтобы на него можно было сослаться в задании. Результаты студента сохраняются в его рабочем каталоге, который не требуется включать в исходные материалы курса.

### Демонстрация 7

Полный запускаемый пример: [examples/section_07.py](examples/section_07.py).

```python
import json

original = {"version": 1, "students": [{"grades": [4]}]}
restored = json.loads(json.dumps(original))
assert restored == original

print(original["students"][0]["grades"])

```

**Ожидаемый вывод:**

```text

[4, 5]
```
