## 1. Запись как словарь

Словарь связывает ключи со значениями. Одна запись о студенте содержит несколько разных характеристик: ID, имя, группу и список оценок. Имена ключей делают назначение полей явным. Если использовать список ["S01", "Анна", "ИС-21", [4, 5]], придётся помнить смысл каждого индекса. Словарь позволяет обращаться к student["name"].

Договоритесь об одинаковых ключах во всех записях. В одной записи нельзя использовать name, а в другой full_name, если функции ожидают единую схему. Схема — это описание обязательных полей и их типов. Пока мы соблюдаем её вручную; позднее проверка станет частью класса.

Квадратные скобки подходят для обязательного поля: отсутствие ключа означает, что данные нарушают договорённость. get удобен для необязательного поля, когда отсутствие предусмотрено. Не следует заменять каждое обращение на get: это может скрыть ошибку в названии ключа и отложить проблему до другого участка программы.

### Демонстрация 1

Полный запускаемый пример: [examples/section_01.py](examples/section_01.py).

```python
student = {"id": "S01", "name": "Анна",
           "group": "ИС-21", "grades": [4, 5]}
print(student["name"])
print(student.get("email", "не указан"))
student["grades"].append(3)
print(student["grades"])
```

**Ожидаемый вывод:**

```text
Анна
не указан
[4, 5, 3]
```

## 2. Словарь записей по ID

У разных студентов могут совпадать имена. Поэтому имя не подходит как надёжный идентификатор. В учебном журнале используем отдельный строковый ID. Внешний словарь связывает ID с записью: book["S01"] возвращает конкретного студента. Число в строке и число как int — разные ключи, поэтому единый тип ID принципиален.

Вставка book[id] = record заменяет старое значение, если ключ уже существует. Для учебного журнала такое молчаливое обновление опасно: можно потерять оценки. Сначала проверяем наличие ключа. На этой лекции функция возвращает bool, а в семестровой работе позже будет установлен контракт с ValueError. Контракт учебного упражнения не следует автоматически переносить в итоговое API.

Для поиска по ID словарь удобнее полного перебора списка. Но для поиска по части имени всё равно нужно просмотреть записи. Выбор структуры зависит от наиболее частых операций, а не от того, какая конструкция выглядит короче.

### Демонстрация 2

Полный запускаемый пример: [examples/section_02.py](examples/section_02.py).

```python
def add_record(book, record):
    key = record["id"]
    if key in book:
        return False
    book[key] = record
    return True

book = {}
print(add_record(book, {"id": "S01", "name": "Анна"}))
print(add_record(book, {"id": "S01", "name": "Борис"}))
print(book["S01"]["name"])
```

**Ожидаемый вывод:**

```text
True
False
Анна
```

**Вопрос для обсуждения:** Почему нельзя использовать фамилию как уникальный ключ?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 3. Поиск и фильтрация

Поиск по условию строится знакомым циклом: просмотреть элементы, проверить условие, добавить подходящие в новый список. Фильтрация не должна менять исходную коллекцию. В примере требуется точное совпадение группы: ИС-21 и ис-21 считаются разными строками, пока явно не задано правило нормализации.

Обсудите отличие пустого результата от ошибки. Если в группе нет студентов, пустой список является нормальным ответом. Вызывающий код решит, показать ли сообщение «Записей нет». Возвращать иногда список, а иногда строку «не найдено» неудобно: каждый потребитель будет вынужден разбирать два несвязанных типа.

Списковое включение способно записать ту же операцию короче, но сначала важно понять обычный цикл. На практике допустимы оба варианта. Критерий — студент может объяснить условие включения записи и предсказать результат для пустого входа.

### Демонстрация 3

Полный запускаемый пример: [examples/section_03.py](examples/section_03.py).

```python
def select_group(students, group):
    result = []
    for student in students:
        if student["group"] == group:
            result.append(student)
    return result

rows = [{"name": "Анна", "group": "A"},
        {"name": "Борис", "group": "B"}]
print(select_group(rows, "A"))
```

**Ожидаемый вывод:**

```text
[{'name': 'Анна', 'group': 'A'}]
```

**Вопрос для обсуждения:** Будут ли словари внутри result независимыми копиями?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 4. Изменение и удаление записи

Перед изменением нужно определить, какую запись меняем и что делать, если её нет. В учебном примере сначала используем membership-проверку key in book. Затем изменяем конкретное поле. Удаление через del удаляет связь ключа и записи во внешнем словаре. Оно не означает автоматического удаления всех других ссылок на этот объект.

Нельзя бездумно удалять элементы словаря во время обхода того же словаря: меняется размер коллекции, что нарушает обход. Если задача — удалить несколько записей по условию, сначала соберите их ключи в отдельный список, затем выполните удаление по этому списку. Так алгоритм остаётся понятным.

В интерфейсе перед удалением потребуется подтверждение пользователя. Однако вычислительная функция не должна спрашивать подтверждение через input. Интерфейс получает ответ, после чего вызывает функцию удаления. Эта граница сохраняется и при переходе к классам.

### Демонстрация 4

Полный запускаемый пример: [examples/section_04.py](examples/section_04.py).

```python
book = {"1": {"name": "Анна", "group": "A"},
        "2": {"name": "Борис", "group": "B"}}
book["1"]["group"] = "B"
keys = [key for key in book if book[key]["name"] == "Борис"]
for key in keys:
    del book[key]
print(book)
```

**Ожидаемый вывод:**

```text
{'1': {'name': 'Анна', 'group': 'B'}}
```

**Вопрос для обсуждения:** Зачем нужен отдельный список keys?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 5. Группировка и подсчёт

Группировка отличается от фильтрации: нам нужны все группы сразу. Создаём словарь, в котором ключом будет название группы, а значением — список её студентов. При первом появлении группы создаём пустой список. Затем добавляем запись в список соответствующей группы.

Частотный подсчёт использует ту же идею, но хранит число вместо списка. Если ключа ещё нет, счётчик начинается с нуля. Выражение counts.get(group, 0) + 1 удобно показывает начальное значение. Важно не создавать пустой список повторно на каждой итерации: это уничтожило бы уже накопленные записи.

Группировка полезна для отчётов: количество студентов по группам, распределение товаров по категориям, число заявок каждого статуса. Сначала отделяем формирование данных от их печати. Тогда одна функция может использоваться для текстового отчёта и дальнейшего экспорта.

### Демонстрация 5

Полный запускаемый пример: [examples/section_05.py](examples/section_05.py).

```python
students = [{"name": "Анна", "group": "A"},
            {"name": "Борис", "group": "B"},
            {"name": "Вера", "group": "A"}]
counts = {}
for student in students:
    group = student["group"]
    counts[group] = counts.get(group, 0) + 1
print(counts)
```

**Ожидаемый вывод:**

```text
{'A': 2, 'B': 1}
```

## 6. Поверхностная копия и вложенные списки

Копия словаря создаёт новый внешний контейнер, но не копирует вложенный список оценок. Поэтому student.copy()["grades"].append(2) изменит список, который доступен и через исходную запись. Это не ошибка метода copy: он выполняет поверхностное копирование по своему контракту.

Когда схема небольшая и известна, удобно собрать новую запись явно и отдельно скопировать grades. Это показывает, какие данные должны быть независимыми. Существует deepcopy для рекурсивного копирования, но в текущей задаче он скрывает важное для обучения устройство данных. Сначала разберём ручной вариант.

При проверке копирования недостаточно сравнить две записи сразу после создания. Они должны быть равны по содержимому. Затем измените вложенную коллекцию одной записи и убедитесь, что другая осталась прежней. Именно второй шаг выявляет совместное использование списка.

### Демонстрация 6

Полный запускаемый пример: [examples/section_06.py](examples/section_06.py).

```python
original = {"id": "1", "grades": [4, 5]}
copied = {"id": original["id"],
          "grades": original["grades"].copy()}
copied["grades"].append(2)
print(original)
print(copied)
```

**Ожидаемый вывод:**

```text
{'id': '1', 'grades': [4, 5]}
{'id': '1', 'grades': [4, 5, 2]}
```

## 7. Упорядоченный отчёт

Порядок добавления записей не всегда совпадает с порядком удобного отчёта. Для вывода используем sorted с функцией key. Она вычисляет значение, по которому сравниваются записи. В примере основным ключом является имя без учёта регистра, дополнительным — ID. Дополнительный ключ делает порядок однозначным при одинаковых именах.

sorted возвращает новый список, поэтому исходная коллекция не перестраивается. Это особенно полезно, если входом являются значения словаря. У строки casefold назначение связано с сравнением без учёта регистра; исходное имя при этом можно сохранить для вывода.

В учебном журнале применяется лексикографическое сравнение строк Python. Это не полноценная библиотечная сортировка по правилам русского алфавита для всех языковых особенностей. Достаточно явного простого правила, одинакового в программе, задании и тестах.

### Демонстрация 7

Полный запускаемый пример: [examples/section_07.py](examples/section_07.py).

```python
rows = [{"id": "2", "name": "анна"},
        {"id": "1", "name": "Анна"},
        {"id": "3", "name": "Борис"}]
ordered = sorted(rows, key=lambda row: (row["name"].casefold(), row["id"]))
print([row["id"] for row in ordered])
```

**Ожидаемый вывод:**

```text
['1', '2', '3']
```

**Вопрос для обсуждения:** Что произойдёт при одинаковых именах после casefold?
