## 1. Правила нормализации

Нормализация приводит разные записи к выбранному общему виду. Для ФИО в нашем журнале удаляем пробелы по краям и заменяем любую последовательность пробельных символов одним обычным пробелом. Регистр сохраняем: автоматический title может неправильно изменить составные имена и аббревиатуры. Правило должно соответствовать назначению поля.

Выражение " ".join(text.split()) сначала получает слова, разделённые произвольными пробельными символами, затем соединяет их одним пробелом. Оно обрабатывает табуляцию и перевод строки. strip убирает только пробельные символы по краям, поэтому для внутренних повторов его недостаточно.

Очистка не должна незаметно выдумывать отсутствующие данные. Пустое имя после очистки остаётся пустым и позднее будет отклонено проверкой. Также нельзя удалять все пробелы из имени: «Анна Мария» и «АннаМария» будут разными значениями. Сначала формулируем правило, затем выбираем методы.

### Демонстрация 1

Полный запускаемый пример: [examples/section_01.py](examples/section_01.py).

```python
def normalize_name(text):
    return " ".join(text.split())

print(normalize_name("  Анна\t  Иванова\n"))
print(repr(normalize_name(" \t ")))
```

**Ожидаемый вывод:**

```text
Анна Иванова
''
```

## 2. Сравнение без учёта регистра

Для поиска удобно сравнивать нормализованные копии строк. Метод casefold создаёт строку для сопоставления без учёта регистра. Исходное имя сохраняем и возвращаем пользователю в исходном оформлении. Важно применять одно правило к обеим сторонам: и к запросу, и к имени.

Оператор in для строк проверяет вхождение подстроки. Это не поиск целого слова: запрос «ан» может совпасть с разными именами. Такое поведение подходит для простого справочника, если описано в задании. Пустая строка содержится в любой строке, поэтому пустой запрос нужно обработать отдельно. В нашем курсе пустой запрос возвращает пустой список.

Разделите нормализацию имени и нормализацию запроса. Для имени удаляем повторяющиеся пробелы. Для запроса в семестровом контракте достаточно strip и casefold. Если вводить дополнительные преобразования, надо согласовать их с ожидаемыми результатами.

### Демонстрация 2

Полный запускаемый пример: [examples/section_02.py](examples/section_02.py).

```python
def find_names(names, query):
    query = query.strip().casefold()
    if not query:
        return []
    return [name for name in names if query in name.casefold()]

print(find_names(["Анна", "Борис", "Антон"], " АН "))
print(find_names(["Анна"], " "))
```

**Ожидаемый вывод:**

```text
['Анна', 'Антон']
[]
```

**Вопрос для обсуждения:** Почему без проверки пустоты результат будет содержать все имена?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 3. Выделение слов

Для учебного анализатора определим слово как непрерывную последовательность символов, для которых isalpha возвращает True. Всё остальное заменяем пробелом. Полученную строку разбиваем через split. Это правило просто проверить, и оно работает с русскими буквами без ручного перечисления алфавита.

Правило является учебной договорённостью. Оно разбивает «кто-то» на два слова и исключает цифры из слов. Если программе требуется сохранить дефисы или номера моделей, алгоритм нужно изменить вместе с тестами. Не называйте простую токенизацию полноценным лингвистическим анализом: она не объединяет формы «студент» и «студенты».

Заменять разделители пробелами безопаснее, чем удалять: текст «кот,пёс» должен превратиться в два слова, а не в «котпёс». На этом примере хорошо видно, почему короткий код не всегда отражает правильное правило обработки.

### Демонстрация 3

Полный запускаемый пример: [examples/section_03.py](examples/section_03.py).

```python
def tokenize(text):
    chars = []
    for char in text.casefold():
        chars.append(char if char.isalpha() else " ")
    return "".join(chars).split()

print(tokenize("Кот,пёс! КОТ-2."))
```

**Ожидаемый вывод:**

```text
['кот', 'пёс', 'кот']
```

**Вопрос для обсуждения:** Почему удаление запятой в кот,пёс даёт ошибочный результат?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 4. Частотный словарь

После выделения слов можно считать, сколько раз встречается каждое значение. Используем словарь: ключ — слово, значение — число появлений. При каждом слове увеличиваем счётчик. Частотный анализ работает с уже подготовленным списком, поэтому не должен повторно очищать текст внутри каждой итерации.

Обсудите два разных показателя: число слов — длина списка, число различных слов — длина частотного словаря. Для «кот кот пёс» это 3 и 2. Такое различие полезно во многих задачах: число покупок и число разных товаров, число обращений и число уникальных пользователей.

В стандартной библиотеке есть Counter, но сначала реализуем алгоритм вручную, чтобы понять накопление результата. После практики можно показать Counter как готовый инструмент с тем же назначением. Самостоятельное объяснение цикла важнее запоминания одной короткой команды.

### Демонстрация 4

Полный запускаемый пример: [examples/section_04.py](examples/section_04.py).

```python
def frequencies(words):
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    return counts

words = ["кот", "кот", "пёс"]
counts = frequencies(words)
print(counts)
print(len(words), len(counts))
```

**Ожидаемый вывод:**

```text
{'кот': 2, 'пёс': 1}
3 2
```

## 5. Топ слов и устойчивое правило порядка

Для списка самых частых слов сначала превращаем словарь в пары слово–частота через items. Затем сортируем по убыванию частоты. В ключе сортировки удобно использовать отрицательное число: большее исходное значение станет меньшим отрицательным. Вторым элементом ключа используем слово, чтобы при одинаковой частоте порядок был определён.

Срез [:limit] берёт первые limit элементов. В упражнении отдельно договоримся, что при limit <= 0 результат пустой. Без этого отрицательный предел среза означал бы удаление нескольких элементов с конца, что не соответствует смыслу «не показывать ни одного слова».

Детерминированный порядок нужен не только для тестов: два запуска на одинаковых данных должны выдавать одинаковый понятный отчёт. Если при равной частоте требовалось бы сохранять порядок первого появления, это был бы другой контракт. В нашем варианте используется лексикографическое сравнение строк Python.

### Демонстрация 5

Полный запускаемый пример: [examples/section_05.py](examples/section_05.py).

```python
def top_words(counts, limit):
    if limit <= 0:
        return []
    pairs = sorted(counts.items(), key=lambda pair: (-pair[1], pair[0]))
    return pairs[:limit]

print(top_words({"пёс": 2, "кот": 3, "дом": 2}, 2))
```

**Ожидаемый вывод:**

```text
[('кот', 3), ('дом', 2)]
```

**Вопрос для обсуждения:** Зачем второй ключ, если частоты уже отсортированы?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 6. Удаление дублей с сохранением порядка

Множество удобно для проверки, встречалось ли значение раньше. Однако простое преобразование списка в set не выражает требование сохранить порядок первых появлений. Поэтому используем одновременно список результата и множество уже встреченных ключей.

Для каждого имени вычисляем нормализованный ключ. Если ключ ещё не встречался, добавляем его в seen и сохраняем отображаемое имя в result. Если встречался — пропускаем запись. Пустые значения после очистки тоже пропускаем. Так можно считать « Анна » и «АННА» одной записью, сохранив оформление первого появления.

В реальной базе одинаковые имена не доказывают, что речь об одном человеке. Здесь удаляем дубли текстовых строк как отдельное упражнение. В семестровом журнале идентичность определяется ID, и автоматически объединять студентов по имени нельзя.

### Демонстрация 6

Полный запускаемый пример: [examples/section_06.py](examples/section_06.py).

```python
def unique_names(names):
    result, seen = [], set()
    for raw in names:
        name = " ".join(raw.split())
        key = name.casefold()
        if name and key not in seen:
            seen.add(key)
            result.append(name)
    return result

print(unique_names([" Анна ", "Борис", "АННА", ""]))
```

**Ожидаемый вывод:**

```text
['Анна', 'Борис']
```

**Вопрос для обсуждения:** Почему не следует применять это правило для удаления студентов из журнала?

## 7. Последовательность обработки и проверка

Текстовую задачу удобно организовать как несколько этапов: очистка, выделение элементов, анализ, представление результата. У каждого этапа свой вход и выход. Тогда ошибку можно локализовать: если частоты неверны, сначала посмотрим на список слов, а затем на подсчёт.

Для примеров заранее составляем таблицу ожидаемых результатов. Обязательно включаем пустую строку, строку только из разделителей, разный регистр, повторяющиеся слова и случай без пробела после знака препинания. Не ограничиваемся большим произвольным текстом: на нём сложно вручную проверить результат.

При обработке файлов позднее нужно будет различать ошибку чтения и пустое содержимое. Пустой текст является корректным входом анализатора. Это правило позволит использовать те же функции и в консоли, и после чтения файла без дополнительных специальных случаев.

### Демонстрация 7

Полный запускаемый пример: [examples/section_07.py](examples/section_07.py).

```python
def normalize_name(text):
    return " ".join(text.split())

cases = [("  Анна   Иванова ", "Анна Иванова"),
         ("\t\n", ""), ("Борис", "Борис")]
for source, expected in cases:
    assert normalize_name(source) == expected
print("Проверка нормализации завершена")
```
