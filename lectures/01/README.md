## 1. Декомпозиция задачи

Представим, что преподавателю нужен отчёт: сколько оценок у студента, каков средний балл и есть ли двойки. Если поместить ввод, вычисления и печать в один длинный цикл, каждое изменение затронет несколько частей программы. Сначала выпишем отдельные действия и данные, которые им нужны. Вычислению среднего нужен только список чисел. Форматированию нужны имя и готовое среднее. Меню знает, когда вызвать эти операции.

Функция полезна, когда её ответственность можно назвать одним глагольным выражением: «вычислить среднее», «найти задолженности», «сформировать строку». Не следует создавать функцию для каждой строки кода. Граница определяется смыслом и возможностью отдельно проверить результат. Начинаем с конкретного примера и затем заменяем значения параметрами.

При разборе попросите студентов сначала решить задачу словами. Какие значения входят? Что получаем? Изменятся ли входные данные? После этого им легче заметить, что печать результата не является частью самого вычисления.

### Демонстрация 1

Полный запускаемый пример: [examples/section_01.py](examples/section_01.py).

```python
def count_debts(grades):
    count = 0
    for grade in grades:
        if grade == 2:
            count += 1
    return count

print(count_debts([5, 2, 4, 2]))
```

**Ожидаемый вывод:**

```text
2
```

**Вопрос для обсуждения:** Почему функция принимает список оценок, а не читает его через input?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 2. Контракт функции и пустые данные

Контракт описывает допустимые входы, результат и особые случаи. Для average(grades) договоримся: на входе список целых оценок 2–5, на выходе среднее без округления либо None, если оценок нет. Пока проверку неверных типов не реализуем: до лекции об исключениях работаем с корректными входами. Это явное ограничение учебного примера.

Пустой список — допустимые данные, а не обязательно ошибка. Ноль в качестве среднего был бы двусмысленным: это число, которого нет в принятой шкале, но другие функции могли бы ошибочно включить его в статистику. None явно обозначает отсутствие результата. Ветку для пустых данных располагаем до деления, чтобы деление на ноль вообще не выполнялось.

Не округляйте среднее внутри вычисления, если контракт этого не требует. Отчёт может показывать два знака, а последующее сравнение должно использовать исходный результат. Правила представления и правила расчёта выполняют разные задачи.

### Демонстрация 2

Полный запускаемый пример: [examples/section_02.py](examples/section_02.py).

```python
def average(grades):
    if not grades:
        return None
    return sum(grades) / len(grades)

print(average([5, 4, 5]))
print(average([]))
```

**Ожидаемый вывод:**

```text
4.666666666666667
None
```

**Вопрос для обсуждения:** Чем отсутствие оценок отличается от среднего балла 2?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 3. return и print

print отправляет текст в поток вывода. return завершает текущий вызов функции и передаёт значение вызывающему коду. Если функция только печатает среднее, другая функция не сможет получить его для сравнения или записи. При отсутствии явного return Python возвращает None. Это часто объясняет загадочное появление None в выводе начинающих.

Полезно разделить вычисление и оформление. format_average получает уже вычисленное значение и возвращает строку. Тогда одну и ту же функцию можно использовать в консоли, при построении отчёта или в тесте. Формат .2f означает два знака после десятичной точки; это строковое представление, а не изменение исходного числа.

В живом разборе сначала замените return на print и попросите предсказать значение переменной result. Затем верните правильный вариант и покажите, как он участвует в более крупном выражении. Студент должен увидеть поток значений, а не только текст на экране.

### Демонстрация 3

Полный запускаемый пример: [examples/section_03.py](examples/section_03.py).

```python
def format_average(value):
    if value is None:
        return "нет оценок"
    return f"{value:.2f}"

result = format_average(14 / 3)
print("Средний балл:", result)
print(format_average(None))
```

**Ожидаемый вывод:**

```text
Средний балл: 4.67
нет оценок
```

**Вопрос для обсуждения:** Как проверить оформление, не читая текст с экрана?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 4. Параметры и именованные аргументы

Параметр — имя в определении функции, аргумент — конкретное значение при вызове. Значение по умолчанию удобно для часто используемого режима. В примере passing(grades, minimum=3) обычный порог равен трём, но вызывающий код может запросить оценки не ниже четырёх. Именованный аргумент делает смысл вызова заметным без обращения к определению.

Значение по умолчанию вычисляется при определении функции. Поэтому изменяемый список в таком месте может неожиданно сохранять накопленные данные между вызовами. До знакомства с классами придерживаемся простого правила: для необязательной коллекции используем None и создаём новую коллекцию внутри функции. Числа и строки в примере безопасны, потому что они неизменяемые.

Не следует добавлять десяток флагов в одну функцию «на все случаи». Если разные режимы выполняют разные задачи, понятнее несколько функций с отдельными именами. Для учебного курса достаточно позиционных и именованных аргументов, без сложных сочетаний *args и **kwargs.

### Демонстрация 4

Полный запускаемый пример: [examples/section_04.py](examples/section_04.py).

```python
def passing(grades, minimum=3):
    result = []
    for grade in grades:
        if grade >= minimum:
            result.append(grade)
    return result

print(passing([2, 3, 4, 5]))
print(passing([2, 3, 4, 5], minimum=4))
```

**Ожидаемый вывод:**

```text
[3, 4, 5]
[4, 5]
```

**Вопрос для обсуждения:** Что означает minimum=4 в вызове?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 5. Изменение списка и копирование

Имя переменной ссылается на объект. Когда список передаётся функции, новая независимая коллекция автоматически не создаётся. Вызов append внутри функции изменит тот же список, который виден вызывающему коду. Иногда это и требуется, но такой эффект должен входить в контракт.

Если задача — подготовить новый вариант данных, создаём копию внешнего списка. Метод copy достаточен для плоского списка чисел: числа не изменяются на месте. Для списка словарей поверхностной копии уже недостаточно, если планируется менять вложенные значения. Этот случай отдельно появится во второй лекции.

Не считайте любой побочный эффект ошибкой. Метод добавления оценки в журнал обязан изменять состояние. Ошибка возникает, когда изменение неожиданно для вызывающего кода. В названии и описании функции следует сообщить, возвращает она новую коллекцию или меняет переданную.

### Демонстрация 5

Полный запускаемый пример: [examples/section_05.py](examples/section_05.py).

```python
def with_grade(grades, grade):
    result = grades.copy()
    result.append(grade)
    return result

original = [4, 5]
updated = with_grade(original, 3)
print(original)
print(updated)
```

**Ожидаемый вывод:**

```text
[4, 5]
[4, 5, 3]
```

**Вопрос для обсуждения:** Почему нельзя заменить grades.copy() на grades?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 6. Сборка результата из функций

Декомпозиция полезна, когда небольшие функции можно соединить. Сначала вычисляем данные, затем строим результат следующего уровня. В отчёте удобно возвращать словарь с именованными полями: вызывающему коду не нужно запоминать, что означает второй или третий элемент списка. Подробно словари будут разобраны на следующем занятии.

Старайтесь не вычислять одно и то же несколько раз. Сохраните среднее в переменную либо передайте его дальше. Следите за согласованностью: если одна функция обозначает отсутствие значения как None, следующая должна это учитывать. Нельзя без проверки складывать None с числом или форматировать его как float.

Представленный пример намеренно невелик. Для полноценного приложения понадобятся проверка данных, файл и меню. Однако вычислительная часть уже пригодна для тестирования, потому что в ней нет интерактивного ввода.

### Демонстрация 6

Полный запускаемый пример: [examples/section_06.py](examples/section_06.py).

```python
def average(grades):
    return sum(grades) / len(grades) if grades else None

def summary(grades):
    return {"count": len(grades),
            "average": average(grades),
            "debt": 2 in grades}

print(summary([2, 4, 5]))
```

**Ожидаемый вывод:**

```text
{'count': 3, 'average': 3.6666666666666665, 'debt': True}
```

**Вопрос для обсуждения:** Какие три отдельные проверки нужны для summary?

**Короткое упражнение:** измените один вход примера, до запуска запишите ожидаемый результат, затем объясните расхождение, если оно возникло.

## 7. Самопроверка и читаемость

Прежде чем подключать функцию к меню, вызовите её на нескольких небольших примерах. Ожидаемый результат посчитайте вручную. assert подходит для короткой учебной самопроверки: если условие ложно, выполнение останавливается с AssertionError. Проверять введённые пользователем данные через assert нельзя: такие инструкции могут отключаться в оптимизированном режиме Python.

Хорошие имена сообщают назначение: grades, average, count. Однобуквенные имена допустимы в очень коротком локальном фрагменте, но в прикладной программе часто мешают. Комментарий должен объяснять решение, например причину возврата None, а не повторять «увеличиваем счётчик» возле count += 1.

На завершение попросите каждого студента объяснить контракт своей функции соседу. Если объяснение требует описать всё меню, граница функции, вероятно, выбрана неудачно. Задание на практику — улучшить структуру уже знакомой программы, сохранив правильные результаты.
