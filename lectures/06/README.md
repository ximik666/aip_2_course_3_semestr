## 1. Класс и объект

Класс описывает, какие данные и операции объединены одной сущностью. Объект — конкретный экземпляр этого класса. Для журнала студент имеет имя и оценки, а также операции добавления оценки и вычисления среднего. Два студента должны хранить независимые списки.

Метод __init__ инициализирует созданный экземпляр. Первый параметр self обозначает объект, для которого вызывается метод. При Student("Анна") имя передаётся параметру name, а self Python связывает с новым экземпляром автоматически. self.name и локальная name — разные роли: первая хранит состояние объекта, вторая существует как параметр вызова.

Класс не делает программу автоматически лучше. Он полезен, когда данные и правила регулярно используются вместе. Для простого вычисления суммы отдельного списка достаточно функции. В этом курсе ООП вводится через конкретную задачу, без требования превращать каждую вспомогательную операцию в класс.

### Демонстрация 1

Полный запускаемый пример: [examples/section_01.py](examples/section_01.py).

```python
class Student:
    def __init__(self, name):
        self.name = name
        self.grades = []

anna = Student("Анна")
boris = Student("Борис")
anna.grades.append(5)
print(anna.name, anna.grades)
print(boris.name, boris.grades)
```

**Ожидаемый вывод:**

```text
Анна [5]
Борис []
```

## 2. Методы и ответственность объекта

Метод может использовать состояние экземпляра через self. Поэтому average не требует передавать список оценок повторно: он находится в self.grades. Возвращаемое значение при этом подчиняется прежнему контракту: число либо None. Переход к классу не должен незаметно менять смысл вычисления.

Операции ввода и печати оставляем за пределами модели. Метод среднего не спрашивает имя, не читает файл и не формирует меню. Такой класс можно использовать и в консольной программе, и в тесте. Это также упрощает повторное использование уже написанных функций.

Объясните два способа чтения вызова student.average(): «вызвать average для student» и «получить среднее этого студента». Оба помогают понять связь данных и поведения. Если метод никогда не использует состояние объекта, стоит подумать, не лучше ли обычная функция.

### Демонстрация 2

Полный запускаемый пример: [examples/section_02.py](examples/section_02.py).

```python
class Student:
    def __init__(self, grades):
        self.grades = grades.copy()
    def average(self):
        if not self.grades:
            return None
        return sum(self.grades) / len(self.grades)

print(Student([4, 5]).average())
print(Student([]).average())
```

**Ожидаемый вывод:**

```text
4.5
None
```

## 3. Проверка состояния

Объект должен создаваться с допустимыми данными. Если имя пустое, разумнее вызвать исключение при создании, чем получить объект, который позже невозможно корректно отобразить. Нормализацию выполняем до проверки окончательной пустоты: строка из пробелов после очистки не является именем.

Все публичные операции изменения также должны соблюдать правила. Проверка только в __init__ не защитит от добавления неверной оценки через метод. Поэтому общую проверку можно вынести во вспомогательную функцию и вызывать из конструктора и метода добавления. Это уменьшает вероятность расхождения правил.

В учебном проекте атрибуты доступны напрямую, но пользователи класса обязаны менять оценки через add_grade и не менять student_id после включения в журнал. Это договорённость интерфейса. Полное ограничение доступа через свойства и неизменяемые объекты здесь не требуется, чтобы не перегружать тему.

### Демонстрация 3

Полный запускаемый пример: [examples/section_03.py](examples/section_03.py).

```python
class Student:
    def __init__(self, name):
        if not isinstance(name, str) or not name.strip():
            raise ValueError("Имя не может быть пустым")
        self.name = " ".join(name.split())

print(Student("  Анна   Иванова ").name)
try:
    Student(" ")
except ValueError:
    print("Пустое имя отклонено")
```

**Ожидаемый вывод:**

```text
Анна Иванова
Пустое имя отклонено
```

## 4. Общие и индивидуальные атрибуты

Атрибут, присвоенный внутри __init__ через self, принадлежит экземпляру. Изменяемая коллекция, объявленная прямо в теле класса, может оказаться общей для всех объектов. Это типичная ошибка: grades = [] на уровне класса выглядит удобно, но добавление оценки одним объектом становится видимым другим.

Для индивидуального состояния создаём self.grades = [] в конструкторе. Если начальные оценки передаются параметром, используем grades=None и внутри создаём новый список или копию. Не используем [] как значение параметра по умолчанию: он также может разделяться между вызовами.

Проверка независимости требует минимум двух объектов. Добавьте оценку одному, затем проверьте второй. Тест, создающий только один объект, не способен показать совместное использование состояния. Эта ситуация связывает знания о ссылках на коллекции со структурой классов.

### Демонстрация 4

Полный запускаемый пример: [examples/section_04.py](examples/section_04.py).

```python
class Student:
    def __init__(self, grades=None):
        self.grades = [] if grades is None else grades.copy()

a, b = Student(), Student()
a.grades.append(5)
assert b.grades == []
print(a.grades, b.grades)
```

**Ожидаемый вывод:**

```text
[5] []
```

## 5. Композиция: журнал содержит студентов

Композиция означает, что один объект хранит другие объекты и использует их операции. GradeBook содержит студентов, индексированных по ID. Журнал отвечает за уникальность ID и поиск записи. Сам студент отвечает за допустимость своих оценок и расчёт среднего.

Разделение ответственности предотвращает дублирование: GradeBook.add_grade находит студента и вызывает его add_grade. Не нужно ещё раз вручную повторять весь алгоритм добавления в журнале. При изменении правила оценок достаточно обновить Student и его тесты.

В короткой демонстрации используем метод get. В итоговом контракте он называется get_student. Имена учебных фрагментов не заменяют спецификацию проекта. Главное здесь — понять, как экземпляр GradeBook хранит ссылки на Student, а не только строки и числа.

### Демонстрация 5

Полный запускаемый пример: [examples/section_05.py](examples/section_05.py).

```python
class Student:
    def __init__(self, student_id):
        self.student_id = student_id

class GradeBook:
    def __init__(self):
        self.students = {}
    def add(self, student):
        self.students[student.student_id] = student

book = GradeBook()
book.add(Student("S01"))
print(book.students["S01"].student_id)
```

**Ожидаемый вывод:**

```text
S01
```

## 6. Преобразование объекта в словарь

json не знает, как сохранить произвольный Student. Поэтому объект предоставляет to_dict, возвращающий только простые сериализуемые значения. Схема словаря должна соответствовать формату файла: в семестровом проекте используются id, name, group и grades. При этом имя атрибута student_id может отличаться от ключа id.

Список оценок в возвращённом словаре копируем. Иначе вызывающий код сможет изменить состояние студента через подготовленный экспортный словарь. Обратное преобразование from_dict создаёт новый объект, а конструктор повторно проверяет значения. Это позволяет использовать одни и те же правила для ввода и файла.

from_dict удобно оформить через @classmethod. Его первый параметр cls обозначает сам класс, и cls(...) создаёт экземпляр. Для текущего курса достаточно этого простого применения. Не требуется углубляться в метаклассы или сложные фабрики.

### Демонстрация 6

Полный запускаемый пример: [examples/section_06.py](examples/section_06.py).

```python
class Student:
    def __init__(self, name):
        self.name = name
    def to_dict(self):
        return {"name": self.name}
    @classmethod
    def from_dict(cls, data):
        return cls(data["name"])

student = Student.from_dict({"name": "Анна"})
print(student.to_dict())
```

**Ожидаемый вывод:**

```text
{'name': 'Анна'}
```

**Вопрос для обсуждения:** Чем cls в classmethod отличается от self в обычном методе?

## 7. Тестирование класса

Тест класса проверяет и результаты методов, и изменение состояния. Сначала создаём объект с известными данными, выполняем одну операцию и сравниваем состояние или возвращаемое значение. Для неверной операции проверяем исключение и отсутствие изменения.

Особое внимание уделяем независимости: исходный список конструктора, другой экземпляр и словарь to_dict не должны неожиданно менять оценки студента. Журнал, напротив, хранит сам переданный объект Student: это явно описано в семестровом контракте. Нужно различать места, где требуется копия, и места, где общая ссылка является намеренной.

На практике сначала реализуйте минимальный Student, затем добавляйте методы по одному и запускайте проверки. После этого переходите к GradeBook. Одновременная реализация всех файлов затрудняет локализацию ошибки и создаёт лишнюю нагрузку.

### Демонстрация 7

Полный запускаемый пример: [examples/section_07.py](examples/section_07.py).

```python
class Student:
    def __init__(self):
        self.grades = []
    def add_grade(self, grade):
        if type(grade) is not int or not 2 <= grade <= 5:
            raise ValueError("Неверная оценка")
        self.grades.append(grade)

s = Student()
s.add_grade(5)
assert s.grades == [5]
print("Метод изменил состояние по контракту")
```

**Ожидаемый вывод:**

```text
Метод изменил состояние по контракту
```
